# 星际留言服务

作品集的独立留言后台：Vinext / Cloudflare Worker + D1。前台仍部署在原来的 Surge 网址，静态页面本身不保存公开留言。

## 本地维护

需要 Node.js 22.13 或以上版本。进入本目录，运行 `npm run install:ci` 安装锁定版本，再运行 `npm run dev`；本地开发入口默认为 `http://127.0.0.1:5173/`。`npm run build` 生成 Worker 构建。作品集根目录的 Python 构建不安装或发布此后台。

`db/schema.ts` 是表结构；修改后运行 `npm run db:generate`，审阅并提交 `drizzle/` 中生成的 SQL 及迁移记录。部署时按迁移顺序应用到目标 D1；不要在处理访客请求时建表。现有留言迁移到新数据库前需先导出并备份数据，源码仓库不会携带线上评论或访客凭据。

## 部署与换地址

`.openai/hosting.json` 中的项目标识是公开部署元数据，不是访问令牌。维护原服务时保留标识及 `DB` 绑定；另行部署时使用目标平台正式创建的项目标识与 D1 数据库，完成构建、迁移和公开访问设置。不要提交平台登录凭据、`.env*`、`.dev.vars*`、`.wrangler/`、`.sites-runtime/` 或本地数据库。

作品集根目录 `guestbook.config.json` 的 `apiBase` 指向已部署后台的 HTTPS 根地址。换地址后重建前台。允许访问的前台域名在 `lib/guestbook-server.ts` 的 `ORIGINS` 中维护；更换前台域名时同步调整并重新发布后台。上线前从未登录浏览器验证公开读写及跨域请求。

## 站主邮箱验证

每次进入新页面，先选择“访客”或“站主”。访客无需账号即可浏览和留言；站主必须先填写私密发送口令，才能请求发送至预设 QQ 邮箱的六位验证码。发送口令本身不授予站主身份，仍需邮箱验证码验证成功。收发邮箱固定为 `3535348582@qq.com`，请求不能指定其他收件人；缺少配置或发信未确认时不会模拟发送成功。

以下值只配置在托管平台的运行时秘密变量中，不写入源码、构建产物、URL、日志或本地数据库：

- `OWNER_SEND_KEY_SHA256`：私密发送口令的摘要。按顺序连接固定前缀 `JIALE_OWNER_MAIL_SEND_V1`、一个 U+0000 分隔字符、未经裁剪或规范化的口令原串，将完整结果以 UTF-8 编码后计算 SHA-256，保存为 64 位十六进制摘要。口令长度为 16–128 个 JavaScript 字符；不要用公开个人资料代替私密口令。
- `QQ_SMTP_AUTH_CODE`：预设 QQ 邮箱的 SMTP 授权码，不是邮箱登录密码。SMTP 服务固定使用 QQ 的 TLS 连接，不接受访客传入服务器、发件人或收件人。
- `OWNER_OTP_SECRET`：至少 32 个字符的高强度随机秘密，用于验证码和授权令牌的 HMAC；不能与私密发送口令或 SMTP 授权码混用。

发布邮箱验证功能前，先按迁移记录正式应用 `drizzle/0001_owner_email_login.sql`，再部署读取新增表的后台代码；保留原有 `0000` 迁移及线上留言，不要在请求中创建表。后续表结构变化继续通过 `npm run db:generate` 生成新的 SQL、快照和迁移日志，不回改已应用的迁移。

验证码在 SMTP 确认接收后开始计时，一分钟有效、仅能使用一次；同一身份重发会作废旧的未使用验证码。站主授权令牌仅保存在当前页面内存，通过 `X-Owner-Grant` 发送给后台，最长有效八小时。不得把授权令牌或发送口令存入 localStorage、sessionStorage、Cookie、网址或分享链接；新页面及刷新后必须重新选择身份并完成邮箱验证，不能凭本机匿名身份或缓存的站主标记跳过。

服务器将持久的历史站主署名与本次授权分开处理。历史站主留言继续显示站主样式，但站主新发留言、修改身份或删除自己的留言必须有本次有效授权；站主不会获得删除他人留言的额外权限。普通访客继续使用独立的匿名身份、自选昵称和星座。

## 访客交互

无需 GitHub 或其他账号。服务器签发随机的本机匿名身份，数据库仅保存令牌摘要；前台在本机保存该身份，昵称和所选十二星座随评论公开显示。清除浏览器数据后将失去原身份的删除权限，昵称不代表经过验证的真实身份。

API 包括匿名身份创建/更新、公开分页留言、回复、点赞切换及作者软删除；回复通过 `parentId` 关联。正文按纯文本处理，限制长度与发布频率。`@昵称` 是站内文字提及，不发送邮件或跨平台通知。线上数据与源码分开保存。
